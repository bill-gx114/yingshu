# 开发与验证

映述是原生 macOS 应用。产品介绍见[项目介绍](项目介绍.md)，完整操作见[使用说明](使用说明.md)。此文档记录可复现入口与验证范围，不包含本机项目、录音或账号配置。

## 构建

```sh
bash scripts/build-app.sh
```

输出为 `dist/映述.app`。应用层使用系统框架，没有 Swift 第三方包。当前在 Apple Silicon、Swift 6.4 工具链上，以 Swift 5 语言模式和 macOS 14 部署目标构建。建议使用 Xcode 26 / Swift 6.2 或更新工具链，才能编译全部新版 Speech 与 FoundationModels 分支；较旧 SDK 和其他系统组合仍需验证。

独立本地 AI 不包含在 App 中。在 Apple Silicon Mac 上显式准备：

```sh
bash scripts/prepare-local-ai.sh
```

脚本安装独立 Python / MLX，下载固定版本的公开模型并校验哈希与许可。不会读取私人项目或代替用户配置云端密钥。模型与环境位于应用自己的 Application Support 目录。详细依赖、模型和数据边界见[本地 AI 说明](本地AI说明.md)。

### 真实模型检查

先准备本地 AI 环境，再生成诊断音频：

```sh
bash scripts/make-speech-fixture.sh
YINGSHU_LOCAL_AI_REAL=1 bash scripts/check-local-ai-voice.sh
```

诊断句来自 `Tests/fixtures/mandarin-diagnostic.txt`，用 macOS 系统语音在本机生成；仓库不分发该系统语音录音。真实 worker 的公开音频集成检查入口是 `Tests/LocalAIWorkerChecks.py --integration`，需由准备好的 AI 环境中的 Python 运行，测试选项与来源见该文件。

## 已验证与仍需验证

0.11 的历史本机验证包括实际 Qwen ASR / 文字模型运行，以及 App 中固定公开短句的真实 DeepSeek 连接测试；配置密钥不随仓库发布。0.12 的本轮验证集中在项目恢复和输出完整性，重新通过口述工作流的注入检查，没有重新调用真人麦克风、真实模型或计费 API。

0.12 界面离屏检查覆盖 44 个场景、411 项通过断言、0 个错误；新增 10 个保存与素材修复场景。报告另有 58 条边界说明，主要是隐藏窗口无法取得 AX 树或视频合成帧，不能据此声称 VoiceOver、真实键盘事件和全部动态视频界面已通过。重要界面另以 PNG 检查最小窗口、中文长标题、缺失横幅、核验错误及失败重试。

0.12.1 的首次准备流程通过 10 项隔离离线检查，覆盖前置条件、下载校验、并发锁、失败保护、日志与重跑复用；这些检查使用模拟下载和 worker。发布引导另通过 7 项检查，且真实 ZIP 解压后的版本、启动器执行权限、App 与安装支援 worker 一致性、ad-hoc 签名、CRC 和 SHA-256 均通过。语音设置调整后重新通过上述 44 个布局场景，准备步骤先于可选云端配置展示。

0.13 的“我的小人”通过隔离项目的字段兼容、取消无副作用、默认保存、旧工程打开、恢复与撤销重做检查；个人造型通过真实 PNG 与无声 MP4 导出检查，保留三种画幅、文字避让及分层后动作不重置。导出安全和图片导出回归也通过。人物生成和缓存检查不需要访问 AI 模型。

界面重新渲染 49 个场景、450 项通过断言、0 个错误；报告有 71 条环境边界说明，主要是隐藏窗口无法取得 AX 树、SwiftUI 原生控件类型变化及部分视频帧限制。另实际启动 0.13 安装包，确认入口、灵感切换、帽子时发色禁用及 Esc 取消，当前作品保持原样；这不代表完整 VoiceOver 或所有设备已通过。编辑器截图来自隔离示例的真实视图。

0.14 的照片入口扩展了六个照片状态布局场景，总计 55 场景、480 项通过检查、0 个错误、89 条环境边界说明；包括分析中、草稿摘要、失败各两种高度。隐藏窗口的 AX 与 SwiftUI 控件启用态仍受上述限制，未将离屏截图当作完整辅助功能验收。展示截图使用预设造型，不能作为真人转换案例。

照片检测采用 Apple 系统 [VNDetectFaceLandmarksRequest](https://developer.apple.com/documentation/vision/vndetectfacelandmarksrequest)，图片方向参考 [ImageIO 缩略图变换](https://developer.apple.com/documentation/imageio/kcgimagesourcecreatethumbnailwithtransform)。照片分析定向检查还覆盖实际 8 种 JPEG 方向、PNG / HEIC、HEIC 非首张主图与方向、多图容器缩放、40 MB / 一亿像素限制、坏图、无脸和取消。单图用 ImageIO 缩略图，多图 HEIC 显式读取主图，避免缩略 API 错取首图。另将 scikit-image 官方 v0.19.0 的 NASA 公开 astronaut.png 只下载到临时目录，真实通过单脸分析、两人拼图拒绝和旋转元数据复原；该人像没有进入仓库、发行包或展示图。这证明管线可用，不构成相似度或各肤色、光照、机型上的质量基准。[公开样本来源](https://github.com/scikit-image/scikit-image/blob/v0.19.0/skimage/data/astronaut.png)。

照片神韵只保存眼形、眼距、微笑三项离散外观，不存原图、路径或原始人脸点。带这些特征的项目保存、恢复、撤销与个人默认回归通过。真实 PNG / MP4 检查沿用同一造型快照，经典角色仍使用原 PNG；照片入口不调用语音 AI 或云端服务。

同轮还在单独测试目录中，真实下载官方 uv、独立 Python 3.12.14 和 41 个固定版本依赖，建立全新环境；复用已有的 20 个公开模型文件（合计 1,890,942,787 字节），从 Hugging Face 核对固定版本、许可与逐文件哈希，再实际离线加载两个模型通过。再次运行最终准备脚本，确认复用同一环境与模型并再次就绪。模型本体此次没有重新从公网下载，不能将其称为全部资源的首次下载验收。

在这个新环境中，使用系统 Tingting 语音合成仓库内固定中文诊断句，再由真实 worker 完成语音识别和文字整理，返回对应中文且整理实际执行。此项没有使用真人麦克风、私人素材、旧运行环境或云端 API，也没有更改应用原有的 AI 运行目录。

这些结果没有建立用户日常口述的准确率基准，也没有证明优于商业输入法。真人口音、旅行噪声、各机型的真实 iPhone / iCloud 素材、旧版 macOS 和其他 Mac 的完整流程仍需持续试用。布局图是生成示例的真实视图渲染，不代表麦克风识别成功。

## 发布副本

```sh
bash scripts/package-release.sh
```

生成 `dist/release/YingShu-Mac.zip` 和 `SHA256SUMS.txt`。ZIP 使用适合下载平台的英文文件名，包含“映述.app”“准备本地AI.command”“首次使用说明.txt”和“安装支援”。支援文件只精确复制版本库中的准备脚本与同版本 worker，不包含模型、个人项目、原始录音或运行缓存。脚本只处理临时副本：移除编译调试路径和文件扩展属性，重新进行 ad-hoc 签名并核验，再打包；不会修改已安装应用或钥匙串配置。当前没有 Apple 公证或 Intel 发行包。

发布源码前可检查 Git 跟踪内容：

```sh
python3 scripts/check-publication.py
```

该检查只读 Git 跟踪文件，核对本机数据边界、凭据模式、SVG 和入口文档链接；不会读取钥匙串、账号配置、Application Support 或忽略目录。历史本机验证日志与测试产物保留在本地，未纳入仓库。
